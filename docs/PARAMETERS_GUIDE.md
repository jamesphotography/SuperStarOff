# SuperStarOff 参数详解

## 核心概念

SuperStarOff 使用**滑动窗口**方式处理大图像：

```
原理：
┌─────────────────────────────────────┐
│  完整图像 (例如: 8000×6000)          │
│                                     │
│  ┌────┐                             │
│  │512 │ ← 第一个窗口                │
│  └────┘                             │
│      ┌────┐                         │
│      │512 │ ← 第二个窗口（移动stride）│
│      └────┘                         │
│          ┌────┐                     │
│          │512 │ ← 继续滑动...       │
│          └────┘                     │
└─────────────────────────────────────┘
```

## 参数 1: 处理模式 (Mode)

### RGB 模式

**适用场景**：
- ✅ 彩色天文照片
- ✅ DSLR/无反相机拍摄的星空
- ✅ 彩色 CCD 拍摄的深空天体
- ✅ RGB 合成图像

**技术细节**：
- 输入通道：3 (Red, Green, Blue)
- 模型参数：~50M
- 处理对象：彩色星点

**示例**：
```
输入：彩色星空照片
输出：保留星云色彩，移除星点
```

### Greyscale 模式

**适用场景**：
- ✅ 单色 CCD 相机
- ✅ 黑白照片
- ✅ 窄带滤镜拍摄（Ha, OIII, SII 单通道）
- ✅ 灰度图像

**技术细节**：
- 输入通道：1 (Luminance)
- 模型参数：~17M
- 处理对象：灰度星点

**示例**：
```
输入：黑白星空照片
输出：保留星云细节，移除星点
```

## 参数 2: Window Size (窗口大小)

**固定值：512×512 像素**

### 为什么固定？

StarNet++ 模型在训练时使用 512×512 的固定输入：

```
神经网络结构：
输入层: 512×512×3 (RGB) 或 512×512×1 (Greyscale)
  ↓
编码器: 8层下采样
  ↓ 512 → 256 → 128 → 64 → 32 → 16 → 8 → 4
  ↓
解码器: 8层上采样
  ↓ 4 → 8 → 16 → 32 → 64 → 128 → 256 → 512
  ↓
输出层: 512×512×3 或 512×512×1
```

**不建议修改的原因**：
- ❌ 改变 window_size 需要重新训练整个模型
- ❌ 不同尺寸会导致模型失效
- ❌ 跳跃连接 (skip connections) 要求固定尺寸

## 参数 3: Stride (滑动步长) ⭐ 关键参数

### 原理图解

**Stride = 256 (推荐)**

```
图像网格划分：
┌─────┬─────┬─────┬─────┐
│  1  │  2  │  3  │  4  │  每个格子 = 256×256
├─────┼─────┼─────┼─────┤  每个窗口 = 512×512 (覆盖4个格子)
│  5  │  6  │  7  │  8  │
├─────┼─────┼─────┼─────┤
│  9  │ 10  │ 11  │ 12  │
└─────┴─────┴─────┴─────┘

处理顺序：
窗口1: 覆盖格子 [1,2,5,6]     ← 处理中心区域 (256×256)
窗口2: 覆盖格子 [2,3,6,7]     ← 右移 256 像素
窗口3: 覆盖格子 [3,4,7,8]     ← 继续右移
窗口4: 覆盖格子 [5,6,9,10]    ← 下移一行
...

重叠区域 = 512 - 256 = 256 像素
```

### Stride 对比

#### Stride = 128 (高质量)

```
┌──┬──┬──┬──┬──┬──┐
│ 1│ 2│ 3│ 4│ 5│ 6│  每格 = 128×128
├──┼──┼──┼──┼──┼──┤  窗口 = 512×512 (覆盖16个格子)
│ 7│ 8│ 9│10│11│12│
├──┼──┼──┼──┼──┼──┤  重叠 = 512 - 128 = 384 像素
│13│14│15│16│17│18│  重叠率 = 75%
└──┴──┴──┴──┴──┴──┘

优点：
✅ 更多重叠 = 更平滑的边缘融合
✅ 边缘伪影更少
✅ 质量最高

缺点：
❌ 窗口数量 × 4 = 处理时间 × 4
❌ 非常慢
```

#### Stride = 256 (平衡) ⭐ 推荐

```
┌───┬───┬───┐
│ 1 │ 2 │ 3 │  每格 = 256×256
├───┼───┼───┤  窗口 = 512×512 (覆盖4个格子)
│ 4 │ 5 │ 6 │
├───┼───┼───┤  重叠 = 512 - 256 = 256 像素
│ 7 │ 8 │ 9 │  重叠率 = 50%
└───┴───┴───┘

优点：
✅ 质量和速度平衡
✅ 足够的重叠保证融合质量
✅ 推荐用于大多数场景

缺点：
⚠️ 边缘可能有轻微伪影（通常可接受）
```

#### Stride = 384 (快速)

```
┌────┬────┐
│ 1  │ 2  │  每格 = 384×384
├────┼────┤  窗口 = 512×512
│ 3  │ 4  │
└────┴────┘  重叠 = 512 - 384 = 128 像素
              重叠率 = 25%

优点：
✅ 快速 (窗口数量少 ~4倍于stride=128)
✅ 适合快速预览

缺点：
❌ 重叠少 = 边缘融合不够平滑
❌ 可能出现明显的方块伪影
❌ 质量下降
```

### 性能对比表

| Stride | 窗口数量 | 处理时间 | 质量 | 边缘伪影 | 推荐场景 |
|--------|---------|---------|------|---------|---------|
| 128 | 很多 ×4 | 很慢 ×4 | ⭐⭐⭐⭐⭐ | 几乎没有 | 最终成品、要求极高质量 |
| 256 | 中等 ×1 | 中等 ×1 | ⭐⭐⭐⭐ | 轻微 | **日常使用、推荐** |
| 384 | 少 ×0.4 | 快速 ×0.4 | ⭐⭐⭐ | 明显 | 快速预览、测试 |
| 512 | 最少 ×0.25 | 最快 ×0.25 | ⭐⭐ | 严重 | 仅限快速测试 |

### 实际时间对比

以 **8256×5504** 像素图像为例：

| Stride | 窗口数量 | 处理时间 (M1 CPU) |
|--------|---------|------------------|
| 128 | ~960 | ~8 分钟 |
| 256 | ~240 | ~2 分钟 ⭐ |
| 384 | ~110 | ~55 秒 |
| 512 | ~70 | ~35 秒 |

## 边缘融合原理

### 为什么需要重叠？

```
无重叠 (stride=512):
┌────┐┌────┐
│窗口1││窗口2│  ← 边界处理不连续
└────┘└────┘
      ↑
   明显接缝

有重叠 (stride=256):
┌────────┐
│  窗口1  │
└────┬───┘
     │重叠区│
┌────┴───┐
│  窗口2  │
└────────┘
     ↑
  平滑过渡
```

### 融合策略

SuperStarOff 使用**中心区域提取**策略：

```
512×512 窗口处理后，只保留中心 stride×stride 区域：

┌─────────────────┐
│   边缘区 (废弃)   │
│  ┌───────────┐  │
│  │           │  │
│  │  中心区   │  │  ← 只保留这部分
│  │ stride×   │  │
│  │  stride   │  │
│  │           │  │
│  └───────────┘  │
│   边缘区 (废弃)   │
└─────────────────┘

offset = (512 - stride) / 2

例如 stride=256:
- offset = (512 - 256) / 2 = 128
- 保留区域: [128:384, 128:384]
- 丢弃边缘 128 像素（模型在边缘效果较差）
```

## 选择建议

### 场景 1: 日常使用

**推荐配置**：
- Mode: RGB (根据图像类型)
- Stride: **256** ⭐

**适用**：
- 日常天文摄影后期处理
- 平衡质量和速度
- 大多数情况下的最佳选择

### 场景 2: 追求极致质量

**推荐配置**：
- Mode: RGB (根据图像类型)
- Stride: **128**

**适用**：
- 打印输出
- 参加比赛的作品
- 最终成品
- 时间充裕

### 场景 3: 快速预览/测试

**推荐配置**：
- Mode: RGB (根据图像类型)
- Stride: **384** 或 **512**

**适用**：
- 测试参数
- 快速查看效果
- 多次试验
- 不在意质量

### 场景 4: 超大图像 (>100MP)

**推荐配置**：
- Mode: RGB
- Stride: **384** (先快速处理)
- 如满意，再用 stride=256 处理最终版本

**原因**：
- 100MP 图像用 stride=256 可能需要 10+ 分钟
- 先用快速参数确认效果
- 避免浪费时间

对于超大图像，可以裁剪成多个区域分别处理：

```python
# 伪代码
large_image = load_image("huge.tif")

# 裁剪成 4 个区域
top_left = large_image[0:4000, 0:4000]
top_right = large_image[0:4000, 4000:8000]
# ... 处理每个区域

# 拼接结果（需要处理接缝）
```

### 技巧 2: 渐进式处理

```
1. stride=512 快速预览 (~30秒)
   ↓ 效果可以接受？
2. stride=256 正常处理 (~2分钟)
   ↓ 还想要更好？
3. stride=128 高质量处理 (~8分钟)
```

### 技巧 3: 边缘后处理

如果发现边缘伪影：

1. 使用图像编辑软件
2. 对接缝区域轻微模糊
3. 或使用 Photoshop 的 Content-Aware Fill

## 常见问题

### Q: 能否使用 stride < 128？

A: 可以，但不推荐：
- stride=64: 质量提升微小，时间 × 16
- stride=32: 几乎无质量提升，时间 × 64
- 收益递减，不值得

### Q: stride 必须是 2 的幂次吗？

A: 不必须，但推荐：
- ✅ 推荐: 64, 128, 256, 384, 512
- ⚠️ 可用: 100, 200, 300 (但可能有对齐问题)

### Q: 为什么边缘会有黑边？

A: 这是填充 (padding) 造成的：
```
原图边缘需要额外填充以保证完整窗口：
┌─────────────┐
│  原始图像   │
│             │
│        ┌────┼───┐
│        │    │   │ ← 超出边界，需要填充
└────────┴────┘   │
         └────────┘
```
黑边宽度 = offset = (512 - stride) / 2

解决：
- 裁剪黑边
- 或使用镜像填充（待实现）

### Q: RGB 和 Greyscale 能否混用？

A: 不行：
- RGB 模型只能处理 3 通道图像
- Greyscale 模型只能处理 1 通道图像
- 必须匹配图像类型

但可以转换：
```python
# RGB → Greyscale
gray_image = rgb_image.convert('L')

# Greyscale → RGB (伪彩色，无意义)
rgb_image = gray_image.convert('RGB')
```

## 技术细节

### 完整处理流程

```python
def transform(image_path, output_path, stride=256):
    # 1. 读取图像
    image = read_tiff(image_path)  # 例: 8256×5504

    # 2. 归一化
    image = image / 255.0  # [0, 255] → [0, 1]

    # 3. 计算窗口数量
    h, w = image.shape[:2]
    offset = (window_size - stride) // 2  # 例: (512-256)//2 = 128

    num_windows_h = (h - offset*2) // stride + 1
    num_windows_w = (w - offset*2) // stride + 1

    # 4. 填充图像 (确保可被 stride 整除)
    pad_h = num_windows_h * stride - h + offset*2
    pad_w = num_windows_w * stride - w + offset*2
    image_padded = pad_image(image, pad_h, pad_w)

    # 5. 滑动窗口处理
    output = np.zeros_like(image_padded)
    for i in range(num_windows_h):
        for j in range(num_windows_w):
            x = i * stride
            y = j * stride

            # 提取窗口
            window = image_padded[x:x+512, y:y+512]

            # 神经网络处理
            processed = model.predict(window)

            # 只保留中心区域
            center = processed[offset:offset+stride, offset:offset+stride]
            output[x+offset:x+offset+stride, y+offset:y+offset+stride] = center

    # 6. 裁剪回原始大小
    output = output[offset:offset+h, offset:offset+w]

    # 7. 反归一化并保存
    output = (output * 255).astype(uint8)
    save_tiff(output_path, output)
```

## 总结

**最重要的参数**：
1. **Mode**: 根据图像类型选择 (RGB 或 Greyscale)
2. **Stride**: 质量/速度权衡
   - 128 = 最高质量
   - 256 = **推荐平衡** ⭐
   - 384/512 = 快速预览

**Window Size**: 固定 512，不要修改

**记住**：
- 更小的 stride = 更多重叠 = 更高质量 = 更慢速度
- 推荐从 stride=256 开始测试
- 满意后可用 stride=128 处理最终作品
